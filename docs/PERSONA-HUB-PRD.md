# PersonaHub — 产品需求文档

## 1. 产品概述

**产品名称**: PersonaHub
**产品定位**: 输入任意 GitHub 用户 ID，自动生成该用户的技术画像报告
**核心价值**: 帮助用户在短时间内了解一个陌生 GitHub 用户的技术背景、偏好和近 90 天关注领域

**一句话描述**: 不认识某个人？输入他的 GitHub ID，几秒钟后你就知道他擅长什么、关注什么、最近在做什么。

---

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户类型 | 特征 |
|----------|------|
| **HR / 猎头** | 筛选技术候选人，评估候选人的技术栈和开源贡献 |
| **安全研究 / OSINT** | 公开技术背景调研 |
| **普通用户** | 想了解某个技术大神的背景和兴趣 |

### 2.2 典型使用场景

1. **简历筛选**: 收到一份简历，上面写着"活跃开源贡献者"，想知道他具体做了什么、开源贡献的质量如何
2. **社群初识**: 在技术社群遇到一个陌生 ID，想快速了解他的技术方向和活跃程度
3. **候选人评估**: 面试前想通过 GitHub 了解候选人的真实技术偏好、开源偏好和活跃度
4. **安全情报**: 对某个账号做公开技术背景调研，了解其技术领域、活跃时间和关注方向

---

## 3. 核心功能范围

### 3.1 做（本期交付）

- 输入 GitHub 用户 ID，生成该用户的画像报告
- 报告包含：基本信息、技术画像、活跃时间、最近动态
- 无需用户输入 Token
- 分析过程实时流式展示

### 3.2 不做（本期不涉及）

- 用户登录/注册系统
- 分析报告的保存和分享
- 批量分析多个用户
- GitHub 账号关联和长期追踪
- 非 GitHub 平台的数据源

## 5. 输出结果定义

### 5.1 基本信息
- GitHub 用户名、头像、ID
- Bio（个人简介）
- 公开仓库数量、Follower/Following 数量

### 5.2 技术画像
- 编程语言 Top N（基于仓库统计）
- 项目领域（通过仓库名称和描述推断，如：Web 开发、AI 工具、DevOps 基础设施等）
- 开源风格：基于仓库来源判断，自建仓库占比 / 参与他人项目（Fork 后有提交记录或加入 Organization）占比
- 偏好技术（Star 最多的仓库主题、关注的技术方向）

### 5.3 活跃时间
- 主要活跃时段（工作日/周末、白天/深夜，以 UTC 时间为参考）
- 活跃度趋势：基于 GitHub Events API（Push/PullRequestEvent/IssuesEvent/IssueCommentEvent/CreateEvent），统计本月与上月得分，得出"活跃上升 / 保持稳定 / 近期较不活跃"的定性判断；Events 数据不足 30 条则标注"数据不足，无法判断"

- 评分规则：PushEvent +1、PullRequestEvent +1、IssuesEvent +1、IssueCommentEvent +0.5、CreateEvent +0.5；本月 > 上月 20% 以上为上升，反之为下降，差距 20% 以内为稳定。

### 5.4 最近动态
- 近 90 天主要活动类型（提交、PR、Issue、Star 等）
- 近 90 天投入最多的项目
- 近 90 天关注的技术热点

### 5.5 输出格式
- 中文表述
- 结构化 Markdown 格式
- 关键数据以列表/表格形式呈现

## 6. 异常与边界情况

| 场景 | 产品表现 |
|------|----------|
| **用户不存在** | 提示"未找到该 GitHub 用户，请检查 ID 是否正确" |
| **用户存在但公开数据不足** | 各模块根据实际获取到的数据独立分析：基本信息始终正常展示；Repos 数据丰富则分析语言和项目领域；Events 数据丰富则分析活跃时间和近 90 天动态；Stars 数据丰富则分析偏好技术；无数据的模块标注"无公开数据"，不强行生成 |
| **网络请求失败** | 提示"网络异常，分析失败，请重试" |
| **分析超时** | 提示"分析超时，请重试" |
| **API 配额用尽** | 提示"服务繁忙，请稍后再试"（开发者需升级 Token 或增加 Token 数量） |

## 7. 验收标准

### 7.1 功能验收

- [ ] 输入任意有效 GitHub 用户 ID，能返回画像报告
- [ ] 报告包含"基本信息、技术画像、活跃时间、最近动态"四个模块
- [ ] 输入不存在用户 ID，给出明确提示
- [ ] 网络异常时，给出"网络异常，分析失败，请重试"提示
- [ ] 分析超时，给出"分析超时，请重试"提示
- [ ] API 配额用尽时，给出"服务繁忙，请稍后再试"提示
- [ ] 分析过程在界面上实时展示

### 7.2 体验验收

- [ ] 分析过程有合理超时保护
- [ ] 界面在分析过程中无卡顿
- [ ] 错误提示清晰，用户知道如何解决

### 7.3 边界情况验收

- [ ] 用户存在但公开数据不足时，各模块（Repos、Events、Stars）独立分析，能分析多少展示多少
- [ ] API 限流时优雅报错，不出现崩溃
- [ ] 重复提交分析请求时正确处理
